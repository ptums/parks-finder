## 1. Goal

Build a small, polished, accessible web app that helps residents find parks. Residents can see parks on a map, browse a list, and open details. Optional AI-powered search is available. A multi-agent SDLC pipeline builds the app in about 2 hours.

## 1b. Non-negotiables and negotiables

**Non-negotiable (never cut, never deferred, never "fix later"):**

1. **Accessibility.** The target is full conformance with **WCAG 2.2 Level AA** for every view and state. WCAG 2.2 AA is the testable standard behind ADA web-accessibility expectations. Be precise about what this means:
   - The ADA itself has no technical checklist.
   - Automated tools find only a part of real problems.
   - So "complete" here means two things. First, the app meets every applicable WCAG 2.2 A/AA success criterion, and each one has a named test or a documented manual check (FR-16). Second, a human does a real screen-reader walkthrough (FR-17).
   - The README states the standard we target, what we tested, and the known gaps.
   - Without that evidence, the README must **not** claim legal ADA certification or "fully compliant".
2. **Testing.** Every ticket ships tests. The coverage thresholds are enforced. The same checks run in git hooks and in CI (FR-18, FR-19).

**Negotiable (cut first when time is short):** Smooth interactions and transitions, that is: animations, easing, map fly-to, and hover polish. Anything that remains must respect `prefers-reduced-motion`. It must never hide focus or move focus unexpectedly.

## 3. Data handling (`db/parks.sample.json`)

`db/` is a plain folder that holds the JSON. There is no database server.

The brief says that the sample _includes missing or empty values_. It also says: "fields may be missing or null, and arrays may be empty". Image URLs are placeholders ("placeholder images are fine"). You can extend the schema and the data. The README must describe any change ("Dataset changes").

Fields: `id`, `name`, `description`, `location{lat,lng,address}`, `amenities[]` (slugs like `dog-run`), `hours` (free-text string), `images[]` (URLs), `acreage`, `rating`.

| Field                    | Rule                                                                                                                                                                   |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| any optional field       | Missing, `null`, empty string, or empty array => treated as "not provided".                                                                                            |
| `name`, `id`, `location` | These are the only fields a park must have to be usable. `validate:data` reports a record without `id`/`name`. The app skips that record and writes a console warning. |
| `amenities`              | Show them as human labels ("dog-run" -> "Dog run"). Unknown slugs still show, in human form.                                                                           |
| `hours`                  | Show the free text exactly as written. Never parse it, reformat it, or compute "open now".                                                                             |
| `images`                 | URLs can be placeholders or can fail. On error, show a labeled placeholder. Never hotlink-fix or invent images. Alt text: park name + "photo".                         |
| `rating`, `acreage`      | Show them only when they are numeric. Do not use stars as the only signal. Include the number.                                                                         |
| contacts                 | The data has no contact field. The wireframe has a Contacts block. Show "Contact information not listed" (or omit the section). Do not invent contacts.                |
| `location.address`       | It can be a string at neighborhood level. Show it as it is.                                                                                                            |

The Orchestrator profiles the file in Phase 1 (`docs/DATA_PROFILE.md`). It reports surprises at G1.

## 4. UI layout [H] (from the wireframe; single page)

- **Header**:
  - The logo/title as `h1` (top-left).
  - The search input and filters (standard by default).
  - When AI is available: the mode radio group (Filters / AI / Both) and the AI search input.
  - An optional location button.
  - **Reset**. It clears search, filters, selection, and AI state.
- **Directory panel** (left, collapsible): "Park directory" (`h2`), a park filter input, and the list.
- **Map** (main area): one marker per park.
- **Park details** (opened from a marker or the list; popup or dialog, as the architect decides): close button (top-right), image, name (`h2`), description (`p`), amenities (`ul`), address (`h3`), hours (`h3`), contacts (`h3`).
- States to design: loading, empty/no results, AI warming up, AI unavailable, image failed, details for a sparse park.
- Phone: The directory is collapsed by default. Details are usable as a bottom sheet or a dialog.

## 8. Non-functional

- **NFR-1 Accessibility (non-negotiable)**: WCAG 2.2 AA conformance as given in FR-16 and FR-17. Targets are >= 44px (above the 24px minimum). The app works at 200% zoom and at 320px reflow. It respects `prefers-reduced-motion`. It is usable in forced-colors / high-contrast mode (spot check).
- **NFR-2 Resilience**: If any of {AI service, analytics, geolocation, images, tiles} fails, the core experience must not break.
- **NFR-3 Privacy**: See FR-32. The location stays in the browser.
- **NFR-4 Performance**: The first load is usable without waiting on the AI service or the model. The list and the filters feel instant.
- **NFR-5 Cost safety**: Use rate limits, token caps, and query caps. Use an optional daily request cap (`AI_DAILY_REQUEST_CAP`) on the public deployment. Use a cheap default model (`ANTHROPIC_MODEL`). When the app hits the cap, the UI says so, and the standard search/filters continue to work.
- **NFR-6 Quality gates (non-negotiable)**: `npm run check` (prettier check, eslint, typecheck, Jest with coverage thresholds, build) is green. Husky hooks run locally. CI mirrors them and runs Playwright + axe. Every PR has tests.
- **NFR-7 Polish (negotiable)**: Smooth interactions and transitions are nice to have. They are the first things we cut. They never weaken NFR-1.
